Стек технологий:
    backend на django rest framework, frontend на React и SQLite база данных

    Клиентская часть (Frontend):
        Библиотека React — для создания быстрого и отзывчивого пользовательского интерфейса.

    Серверная часть (Backend):
        Язык Python и фреймворк Django — для надежной и быстрой разработки серверной логики.
        Расширение Django REST Framework (DRF) — для построения RESTful API, 
        через которое общаются сервер и клиент.

    База данных:
        SQLite — простая в освоении и легковесная СУБД. Для разработки и тестирования.

    Вопросы:
        Почему Lite?
            Запускается на любом компе.
        А что делать при запуске в продакшн (на реальный сервер)?
            Благодаря ORM в Django, проект не привязан к конкретной СУБД. БД можно легко переключить.
        
        Почему React? 
            ХЗ 
            потому что он позволяет обновлять интерфейс без перезагрузки страниц
        Почему Django DRF?
            потому что он обеспечивает высокую безопасность из коробки и имеет встроеную ORM

        Почему DRF а не просто Django?
            «Связка React + DRF была выбрана для разделения проекта на два независимых слоя: 
            Backend и Frontend.Использование React позволило создать SPA (Single Page Application). Благодаря этому интерфейс работает без перезагрузки страниц, как мобильное приложение: тексты лекций и тесты подгружаются мгновенно.Django REST Framework здесь выступает в роли чистого API, которое просто отдаёт данные в формате JSON. Это делает серверную часть легковесной, а в будущем позволит подключить к этому же бэкенду, например, мобильное приложение без переписывания кода».Точки силы в вашем ответе (что оценит комиссия):Скорость и плавность (UX): В обычном Django при переходе от текста к тесту страница бы полностью перезагружалась. В React меняется только сам контент, что намного удобнее для студента.
            Архитектурный стандарт: Разделение на Frontend и Backend (клиент-серверная архитектура) — это современный стандарт веб-разработки, принятый в индустрии.Масштабируемость: Бэкенд на DRF универсален. 
            Если завтра потребуется сделать приложение для iOS/Android, бэкенд уже полностью к этому готов.
